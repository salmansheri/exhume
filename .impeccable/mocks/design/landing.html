Dig up the files nothing imports.

exhume walks your JS/TS workspace from its entry points and reports every file it never reaches. Across every package, in one pass.

Install from source today (needs Rust)

$ cargo install --git https://github.com/salmansheri/exhume exhume-cli

npm and crates.io packages arrive with the first release.

It follows imports. Whatever it never reaches is dead.

No guessing from file names or timestamps. exhume builds the import graph the way your bundler would, then reports the files left outside it.

Start at the entry points

Each Workspace Package's manifest names where its code begins: main, exports, bin.

Follow every import

Relative paths, imports between Workspace Packages, and tsconfig paths aliases all resolve to real files.

Report what's left

Files no path reaches become Unused Files, grouped by package with the exact location.

  • single package
  • pnpm workspaces
  • npm workspaces
  • yarn workspaces
  • bun workspaces
  • tsconfig paths

Three exit codes. Nothing to parse.

exhume runs unattended. The exit code alone tells your pipeline whether to pass, fail, or flag a broken setup. Every line below is real output from exhume's test fixtures.

Tool error

exhume couldn't scan, and says why.

$ exhume tests/fixtures/yarn-pnp
exhume: Yarn Plug'n'Play (PnP) is not supported; set `nodeLinker: node-modules` in .yarnrc.yml and reinstall
# .github/workflows/exhume.yml
- name: Install exhume
  run: cargo install --git https://github.com/salmansheri/exhume exhume-cli

- name: Find dead files
  run: exhume .

The step fails on exit 1 and the log shows exactly which files to delete.

exhume never modifies your workspace. It reports, you decide.
